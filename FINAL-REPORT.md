## 1. Executive Summary

The BattOpt Control Center went from a catastrophic state (hung shutdown, dead daemon, broken UI, missing installer) to a fully reproducible, self-verifying, and self-maintaining system. This document chronicles the exact state of the project as of the final commit.

## 2. What Was Fixed (The Battle Log)

Over the course of this session, the following critical issues were resolved:

1. **The "4-Hour Hang" (Hung Shutdown):** Two `dispatch.sh shutdown` processes were stuck, preventing the daemon from starting. They were safely terminated, and the state file `.user_shutdown` was cleared.
2. **The "Not Responding" App:** The `/Applications/BattOpt.app` bundle used a Bash script as its executable, which macOS Finder refused to run. It was rebuilt as a native AppleScript Applet (`applet`) that correctly delegates to the shell script.
3. **The Plugin Restoration:** The SwiftBar plugin was missing. It was restored to a full 734-line version with `STATE_COLOR` (dynamic icon colors) and a blue `Sleep Mode` header.
4. **The Missing Installer:** `install.sh` was only deploying 1 out of 19 plists and missing the powerwatch build. It was completely rewritten to be idempotent and comprehensive.
5. **The Sudoers Drift:** Missing `battopt-daemon-restart` and a duplicated `pmset` line caused silent failures. The sudoers file was validated, deduplicated, and properly deployed.

## 3. The 3 Pillars of the New Architecture

### A. `install.sh` (The Builder)
- **What it does:** Deploys everything from scratch.
- **Features:**
  - Deploys all 19 LaunchAgent/LaunchDaemon plists.
  - Copies 15+ daemon helpers to `~/.battopt-swiftbar/` and sets `0755` permissions.
  - Deploys 8 root helpers to `/usr/local/bin/`.
  - Compiles the `powerwatch.c` binary using `/usr/bin/clang`.
  - Validates sudoers before installing it.
  - Runs `verify-install.sh` at the end.

### B. `verify-install.sh` (The Inspector)
- **What it does:** Verifies the entire system state without making changes.
- **Checks (13 Invariants):**
  1. Vendor binary exists.
  2. 8 root helpers exist and are executable.
  3. Root LaunchDaemons are loaded.
  4. 17 user LaunchAgents are loaded.
  5. All `.sh` scripts in `$DASH` are executable.
  6. Sudoers file is valid, no duplicates, has restart grant.
  7. SwiftBar plugin is executable.
  8. BattOpt.app has a Mach-O applet and launcher.
  9. Powerwatch binary is executable.
  10. Config is valid and matches SMC limits.
  11. `.active_mode` is valid.
  12. `battopt status` returns output.
  13. No hung shutdown processes.

### C. `self_maintenance.sh` (The Guardian)
- **What it does:** Runs silently every 5 minutes via `com.battopt.selfmaintenance.plist`.
- **Logic:**
  - Checks daemon responsiveness.
  - Checks SMC hold state (Intelligent logic: only alerts if battery is at 100% config limit but SMC is not holding).
  - Checks for hung processes.
  - Checks `/var/vm` disk space for sleepimage.
  - Checks for Guardian process storms (>5 instances).
- **Action:** If `[FAIL]`, it sends a `terminal-notifier` alert to the user. If `[PASS]`, it prints a single line to the log.

## 4. The Golden Rules (Lessons Learned)

This project enforced strict rules to prevent AI hallucination and state corruption:

1. **No AI writes to disk directly:** AI outputs `cat > file << 'EOF'` blocks. The human (or terminal) executes them.
2. **Verify before commit:** Every file generated by AI must pass `bash -n` (syntax) or `plutil -lint` (plist) before being committed.
3. **Atomic Commits:** One fix per commit, ensuring `git revert` can undo a specific mistake without breaking everything else.
4. **Rollback Anchor:** The tag `pre-astra-audit-20261021-2358` and `v1.7.0-final-20261022-0341` are permanent restore points.
5. **No Guessing:** If a file path or sudo command is not verified in the codebase, AI is forbidden from assuming it exists.
